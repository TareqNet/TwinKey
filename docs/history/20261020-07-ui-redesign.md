# UI Redesign — Refined Minimal, No Bootstrap

> Date: 2026-10-20
> Type: Feature
> Ticket: N/A
> Branch: `feature/ui-redesign` (stacked on `fix/functional-bugs`)
> Author: Tareq Nassry (with Claude Code)
> Stack: Vanilla JS, native CSS custom properties, `<dialog>`, Popover API, inline SVG sprite

---

## Summary

Rebuilt the popup UI in a calm "Refined Minimal" style: neutral surfaces, one indigo accent, soft cards, one shared countdown ring, light/dark/system themes. Bootstrap (CDN CSS, icon font, custom JS shim) is gone; the extension is now fully offline and the CSP has no external hosts and no `'unsafe-inline'`. All DOM is built with `createElement` / `textContent`, so user data can no longer be parsed as HTML.

---

## Proposed Plans

**Options Considered (user chose 2026-10-20):**

1. **Refined Minimal** — neutral surfaces, single accent, soft cards, global countdown ring. ✅ Chosen
2. **Soft Gradient / Glass** — gradient header, frosted cards. More CSS, blur contrast risk.
3. **Compact List** — dense authenticator rows, folders as a dropdown.

**Bootstrap:** removed in favour of native CSS (vs. vendoring locally) — drops ~230 KB, enables strict CSP, fits the redesign.

### Phase 2 — Review fixes (2026-10-20)

**Request summary:** Post-implementation review of the four stacked branches found one blocking bug and two smaller ones that the first smoke run did not cover.

**Key discussions:**
- Change PIN rewrote every ciphertext in storage, but `PopupManager.accounts` kept the old objects. Accounts already in the secret cache kept working (cache keyed by old ciphertext), so the first test passed; any account not yet decrypted (other folder, filtered by search) showed "Can't decrypt" until the next lock. Fix: after `rekeyVault()` clear the cache, reload accounts, re-render.
- `addAccount` used `accounts.length` as `sortOrder`; after a delete it could collide with an existing slot, making Move up/down and drag a no-op until the next unlock. Fix: `max(sortOrder) + 1`.
- Old installs carry `otp_settings.theme: "light"` written by the old defaults (never a user choice), which would pin upgraded users to Light. The picker now writes `otp_settings.appearance`; legacy `theme` is ignored.
- Headless finding: Chrome defers `<dialog>` `close` events to the next rendering update, which never happens in a hidden tab. Product unaffected (popup is always visible); the test brings the tab to front.

**Tools & libraries:** None added. Headless Chrome for Testing 148 via CDP (scratch script, not committed), DOM assertions only — no screenshots (user on limited mobile data).
